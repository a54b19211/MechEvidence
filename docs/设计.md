# MechEvidence 设计与开发约定

README 讲怎么用、接口和评级规则；这里讲为什么是这个形状、改代码时守什么。

## 代码地图

| 文件 | 做什么 |
|---|---|
| `mechevidence/service.py` | FastAPI 入口，默认端口 18563（`DEFAULT_PORT`，环境变量 `PORT` 可改） |
| `mechevidence/models.py`、`contract.py` | 请求模型（拒绝契约未写的字段）；`contract.py` 校验后交给 v2 规则 |
| `mechevidence/v2.py`、`v2_rules.py` | v2 评价、evaluator id、reuse key、回执回显、`adopt()` |
| `mechevidence/receipt.py` | 回执格式表 `SHAPE`、跨字段规则及其 JSON Schema（`GET /v2/contract` 发布） |
| `mechevidence/identity.py` | `current_evaluator()`：评价器身份的唯一出处 |
| `mechevidence/authorization.py` | 每次模型请求前的授权和请求后的结果交回 |
| `mechevidence/llm.py`、`prompts.py` | 模型调用（`openai` 库，自带重发关掉，先存档再解析）和两次调用的提示词 |
| `mechevidence/materials.py`、`source_identity.py` | 材料可评性、文献身份与来源合组 |
| `mechevidence/assess.py` | 程序评级（`aggregate`），`RULES_VERSION` |
| `examples/contract-v2/` | v2 契约夹具，由 `tests/contract_cases.py` 生成 |

## 为什么是同步服务、两次小调用、程序编号

旧版的验收在审阅阶段报 `model_output_invalid`：旧 schema 要模型自己维护观察编号、片段编号和带绝对字符偏移的出处，错一个整份作废；服务还把模型请求交回雷达代调再回放。现在：

- 服务自己调模型，一次请求就是一次同步 HTTP 调用。
- 两次调用（拆解、审阅）、两份小 schema；编号全部由程序分配，坏的一条只丢一条；思考关闭，`max_tokens` 4096，校验失败带错误重试一次。
- 旧的局部审阅与机制审阅合并为一次；偏移锚点、组合、两两比较、整体评估、消融开关、队列独立性评审、Fabric 读取都删掉了。确定性评级规则保留（README「怎么评」）。

## 版本绑定契约（v2）

v1 对不认识的字段（`version_id`、binding）静默丢弃还答 200，回答里也不说是谁评的，结果既不能复现、缓存，也不能审计。v2 把评价绑到命题、范围、固定版本的材料和评价器上。

- **两套并存。** `/v1/evaluate` 算法不变，标为兼容结果（`binding_state: unbound`、`reusable: false`），未知字段也报 422；旧记录不事后补评价器或绑定。`/v2/evaluate` 所有请求模型都拒绝未知字段；模型输出的模型保持宽松。
- **材料绑定。** 每份材料带雷达建的 binding（整串 sha256 和长度、literal 段、part 段：来源、记录、版本、原件哈希、处理器版本、段哈希和定位）。服务只能核文字与绑定自洽（`self_consistent`）；是不是那个固定版本的那一段，由雷达发出前向 Fabric 重读保证。
- **评价器身份。** `evaluator_id = sha256(规范化的 {service, contract_version, rules_version, ordering_rule, batch_size, 两份提示词的 sha256, model_config{provider, model, thinking, temperature, max_tokens, endpoint_id}})`；`code_version` 只作审计。同样的观察会得出不同结论的改动（范围别名表、比较与评级规则、可评性、来源合组）都要升 `RULES_VERSION`。
- **范围三态。** 物种/系统/疾病各为 `stated`、`unknown`、`not_required`；空串算 unknown，unknown 从不算匹配。
- **复用键（第一期，保守）。** 覆盖评价用到的每个输入：命题、规范化范围、**有序**材料列表（含调用方别名、绑定哈希、标题、类型、层级、身份字段和合组结果）、批大小、评价器 id。别名进键，是因为模型看到的编号和片段序号都由它们和顺序决定。代价是缓存不命中，不是命中错。顺序无关要等评价器规范排序并重映射所有引用，那是下一个规则版本。
- **评价器竞争。** `expected_evaluator_id` 与当前不符 → 409 `evaluator_changed`，什么都不评、不调模型。
- **每次模型请求前现查授权。** 调用方给不透明的 `authorization_ref`；每个实际 HTTP 请求（含格式重试）前，服务向环境里配置的可信端点查授权，只有 200、`valid`、带决定号、回显本次 attempt/评价键/评价器且未过期才发；每次请求后交回结果，对方逐字段确认才算记下，没记下就不再发。端点从不取自请求。v1 在一次请求内不复查，这是写明的兼容缺口。
- **原始回答。** `llm_calls[].outputs` 每个实际请求一条，原文（≤256 KiB）和整份哈希先存档再解析；信封读不出来记 `response_malformed`，整体是可处理的 502；超长 → 502 `output_oversize`，不出结论、不做格式重试。截断的哈希从不冒充整份的哈希。
- **规则只有一个主人。** `POST /v2/reuse-key` 返回评价器、reuse key 和材料回显，调用方据此查缓存，不自己算；服务返回 200 前对自己的回执跑 `contract.adopt()`，不过就 502 `receipt_invalid`。`adopt()` 对畸形回执从不抛异常：先按 `receipt.SHAPE` 查类型（bool 不是 int）、枚举和哈希形式，再查跨字段规则，最后核请求身份；失败分为 `receipt_invalid`、`receipt_mismatch`、`audit_incomplete`，都保留原始回执，结论不可采用、不可缓存。新回执字段就加进这张表，夹具上的类型变异矩阵会证明它。

## 开发约定

**代码**

1. 普通函数和直接调用，一个文件一类职责；不建插件框架、注册中心、通用 Agent 或队列。
2. 模型调用只走 `llm.chat_json`；先存档原始 HTTP 回答再解析，已发出的请求不因解析失败而丢失。
3. 编号由程序分配（C/J、E1.3、O），模型只引用；无效编号、找不到的短引只丢那一条，记进 `material_notes`。
4. schema 要小：每次输出不超过两层、必填字段不超过 5 个、枚举用小写英文。
5. 哈希、评价器身份和回执只属于 `/v2/evaluate`；兼容路径不加。调用记录存 stage、model、usage、finish_reason、耗时、错误码和实际请求数（`requests`）。
6. 注释解释医学或算法原因，不复述代码；同一规则只维护一处（评级在 `assess.py`，可评性和身份在 `materials.py`）。

**证据完整性**

7. 模型负责有出处的语义判断，程序负责覆盖、范围、因果要求、冲突和去重；不用总分代替分析。
8. 因果结论只认干预 + 直接检验 + 原始研究结果；综述、图谱、登记/方案、新闻和声明不升级为实验结果；机制推断不升级为临床有效性，细胞或动物终点不替代患者终点。
9. 不同范围是适用性缺口，不是反证；情境不能确定可比的反向结果保留为未解决。来源去重不等于队列或实验独立。
10. 「本材料包未报告」不等于「未实施」或「阴性」；失败给出可处理的原因，不写成科学结论。
11. 用真实材料检验支持、反证和误报；模型自评不当专家标签，不靠重复调用刷结果。

**契约**

12. 任何会让同一输入得出不同结论的改动（提示词、范围别名表、比较与评级规则、批大小、默认模型）都要升 `assess.RULES_VERSION` 或改变评价器身份的字段，并在本文件记一笔。
13. 复用键必须覆盖评价实际用到的每个输入；给材料加字段，先在 `tests/test_contract_v2.py` 加扰动用例。
14. 改了契约、提示词或规则后用 `MECH_REGEN_FIXTURES=1 python -m pytest tests/test_contract_fixtures.py` 重生 `examples/contract-v2/`，并在提交里说明。

**其他**

15. 测试只覆盖真实错误和容易误伤的正确例子，不联网（`python -m pytest -q`）。
16. 密钥放私有 .env 或部署环境；数据和运行结果放忽略目录；凭据和隐藏思考不进仓库或报告。
17. 文档只有两份：README.md 和本文件。
